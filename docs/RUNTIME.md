# Passbolt MCP

Самостоятельный сервис для Passbolt: безопасные метаданные, выбор ресурса,
создание и обновление ресурсов, папки, выдача прав и использование секрета
через зарегистрированный серверный обработчик. Пароли, JWT, GPG-ключи и
passphrase остаются на сервере. AI Kit и `mcp_platform` для запуска не нужны.

В `contracts/tools.json` сохранены восемь исходных инструментов с прежними
именами, параметрами, ответами и описаниями. Код API/GPG/JWT/v5 metadata и
инструментов развивается в этом репозитории.

## Установка

Нужны Python 3.12–3.14 и системный GnuPG. GnuPG в wheel не включён.
Оператор предоставляет приватные файлы конфигурации, ключи и разрешения.

```sh
uv sync --frozen --extra standalone
uv run --frozen --extra standalone passbolt-mcp --transport stdio
uv run --frozen --extra standalone passbolt-mcp --transport http --host 127.0.0.1 --port 8817
```

HTTP использует Streamable HTTP на `/mcp`. Публичный ключ RS256 обязателен.
JWT должен иметь точные `iss`, `aud`, действующий `exp`, `sub` из операторской
таблицы привязок, `account_id` и scopes. Токен не меняет vault, привязки или квоты.

| Переменная | Назначение / значение по умолчанию |
|---|---|
| `PASSBOLT_SECRET_FILE` | Абсолютный путь к приватному env из `examples/passbolt.env.example` |
| `PASSBOLT_BINDINGS_FILE` | Приватный JSON: клиент → имя привязки |
| `PASSBOLT_STATE_PATH` | SQLite журнала, `state/passbolt.sqlite` |
| `PASSBOLT_ACCOUNT_ID` | Контур состояния, `default` |
| `PASSBOLT_LOCAL_PRINCIPAL` | Клиент stdio, `local-operator` |
| `PASSBOLT_LOCAL_SCOPES` | Scopes stdio, `passbolt:read` |
| `PASSBOLT_MCP_PUBLIC_KEY_FILE` | PEM публичного ключа, обязателен для HTTP |
| `PASSBOLT_MCP_ISSUER` / `PASSBOLT_MCP_AUDIENCE` | `passbolt-operator` / `passbolt-mcp` |
| `PASSBOLT_WRITE_ENABLED` / `PASSBOLT_USE_ENABLED` | Оба `false`; включаются оператором отдельно |
| `PASSBOLT_ENABLED` | `true` |
| `PASSBOLT_RATE_LIMIT` | До 10 сетевых попыток в минуту на vault, по умолчанию 10 |
| `PASSBOLT_SELECTION_TTL` | 60–600 секунд, по умолчанию 600 |

Пример привязок для одного vault: `{"local-operator":"owner_all"}`.
Для нескольких vault используется `PASSBOLT_PROFILE_REGISTRY_FILE`:
`examples/profile-registry.json` связывает привязку с отдельным env-профилем
и политикой. Оператор ограничивает пример политики нужными ресурсами,
доменами и правами. Пустой список sinks запрещает доставку секрета.

Custody-файлы должны иметь абсолютные обычные пути: на Linux — 0600 для
файлов, 0700 для каталогов, владелец root или пользователь сервиса; на Windows
— приватные ACL, настроенные оператором. Токены и sealed refs доступны для
записи сервису; исходные ключи и реестр политик предоставляются с ограниченными правами.

## Инструменты и подтверждения

- `passbolt_status`, `passbolt_search`, `passbolt_select`, `passbolt_local_diagnostics`: `passbolt:read`.
- `passbolt_create_resource`, `passbolt_update_resource`,
  `passbolt_create_folder`, `passbolt_share_resource`: `passbolt:write`.
- `passbolt_use_secret`: `passbolt:use`.

Для операции, требующей подтверждения, первый вызов возвращает `approval_id`.
Доверенный оператор принимает конкретную запись вне MCP-интерфейса. Клиент
повторяет исходный вызов с `approval_id`.

```sh
uv run --frozen --extra standalone passbolt-approval APPROVAL_UUID
uv run --frozen --extra standalone passbolt-approval APPROVAL_UUID --accept --principal CLIENT --request-hash SHA256
```

Запись содержит владельца, операцию, хеш запроса, срок и статус. Оператор
сверяет её с подготовленной операцией; исходные аргументы и секреты в журнал
не записываются. Одобрение используется один раз. Обновление проверяет
`expected_modified`; выдача прав ограничена серверной политикой. Создание
без выдачи прав разрешено только политикой vault.

`secret_source` принимает `server_generated` либо непрозрачный `sealed_ref`
на подготовленный сервером файл. Пароль, путь к ключу или команду sink через
MCP передавать нельзя. Producer API в этой версии нет: входящий файл готовит
оператор отдельным доверенным каналом.

Выбор секрета привязан к клиенту, vault и точному URL. Перед доставкой заново
проверяются политика ресурса, домена и sink. Выбор потребляется до доставки;
ошибка или отмена не разрешают повторное использование. Несовпадение доменов
требует отдельного одобрения. Результат доставки — только boolean.
Обработчики `secure_fill`/`out_file` выбираются из серверного реестра;
абсолютный исполняемый файл проверяется по SHA-256, stdout/stderr подавляются.
Примеры потребителей: `examples/sinks/`.

Встроенный `https_probe` выполняет один запрос на фиксированный HTTPS-адрес:
[диагностика и настройка](SECRET_PROBE.md). Он использует прежние проверки выбора
и разрешений; проверка TLS включена, редиректы и повторы отключены.

## Состояние и повторы

Процессы одной конфигурации vault должны использовать общую приватную SQLite.
Совпадающие URL, service user и fingerprint разделяют квоту независимо от
имени профиля. Допускается одно исполнение на vault; учитываются первые
HTTP-запросы и повторы. Deadline MCP — 300 секунд. После отмены или deadline
сохраняется lease до 900 секунд из-за возможного завершения GPG/sink процесса.

Журнал хранит ключ, хеш, владельца, статус и безопасный результат. Неизвестный
исход остаётся `pending`; новый ключ не обходит запрет повторной операции.
Создание с выдачей прав сохраняет созданный ID через checkpoint: возобновляется
выдача прав. Checkpoint обновляется с проверкой ожидаемого значения и lease.

Доказанный отказ локальной квоты до любой сетевой попытки внутри write factory
получает `failed`. Повтор требует нового ключа и необходимого нового одобрения.
После допущенной попытки такая классификация запрещена. Счётчик учитывает
запросы дочерних asyncio-задач того же исполнения.

При перезапуске сверяется fingerprint привязок и env-конфигурации профилей.
Подмена маршрута при прежней базе отвергается. Изменения требуют отдельной
миграции оператором; удаление базы или смена `account_id` не являются способом
повторить неизвестную запись. Автоматической сверки с API нет.
Readiness сохраняет исходное поведение: часть ошибок probe отражается флагами
`auth_ready`/`decrypt_ready`, без раскрытия текста исключения.

## Разработка и платформа

```sh
uv run --frozen --extra standalone python scripts/verify.py
uv build
```

Тесты используют синтетические ответы; реальные vault API запрещены.
Проверки POSIX permissions/symlink выполняются на Linux. Источник, SHA файлов
и изменения записаны в `SOURCE_PROVENANCE.json`.

Платформа устанавливает точный wheel с SHA-256 без extra `standalone` и
внедряет свои auth/scopes, store, approvals, quota и audit. Самостоятельная
SQLite/runtime в этом режиме не запускается. Внешние интерфейсы прежние.
Отдельный контейнер для сервиса не обязателен.
