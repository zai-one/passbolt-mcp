# Passbolt MCP

**Работайте с хранилищем паролей прямо из AI-ассистента.**

> MCP-сервер для менеджера паролей Passbolt: агент ищет, организует, шарит и использует учётные данные из хранилища, а пароли никогда не попадают в диалог.

Найдите нужную учётную запись, наведите порядок в хранилище и подготовьте доступ коллеге в одном диалоге. Passbolt MCP подключает ассистента к вашему хранилищу и не возвращает пароли в ответах MCP. Если задаче нужен секрет, сервер передаёт его обработчику, который вы настроили.

[Установка](#установка) · [Подключение к ассистенту](#подключение-к-ассистенту) · [Issues](https://github.com/zai-one/passbolt-mcp/issues)

Например, попросите ассистента:

> Найди запись для https://example.com. Покажи название и логин, чтобы я выбрал нужную учётную запись.

## Что можно сделать

| Задача | Возможности MCP |
|---|---|
| Найти учётную запись | Поиск по метаданным и выбор записи для конкретного URL. В результатах виден тип записи (например, `v5-default` или PIN-код `v5-pin-code` из Passbolt 5.12), но не её секрет. |
| Навести порядок в хранилище | Создание и обновление записей, папок и прав доступа в пределах вашей политики. |
| Использовать секрет в автоматизации | Передача выбранного секрета зарегистрированному серверному обработчику; ассистент получает результат выполнения. |
| Проверить защищённый адрес | Готовый HTTPS-обработчик использует выбранную запись; ассистент получает результат без пароля и тела ответа. |
| Разобраться с настройкой | Локальная проверка работоспособности ключа, публичного ключа сервера и политики доступа до подключения к хранилищу. |

[Сценарий проверки защищённого адреса](docs/SECRET_PROBE.md#русский) содержит пример приватной настройки, запросы и команду диагностики `passbolt-mcp-doctor`.

## Почему этот MCP

- Ленивая загрузка инструментов (опционально): `PASSBOLT_TOOL_LOADING=lazy` (или выбор в мастере настройки) — старт с небольшим ядром, наборы включаются по запросу; см. [Ленивая загрузка инструментов](#ленивая-загрузка-инструментов).
- Ни один инструмент не возвращает пароль: секреты уходят только в зарегистрированные оператором приёмники (secure fill, файл, HTTPS-проба), ассистент получает статус.
- Наборы инструментов (meta, read, use, write); `PASSBOLT_READ_ONLY=1` оставляет только чтение метаданных; шаринг по политике доступа.
- Локальный `passbolt-mcp-doctor` проверяет ключи и политику до подключения; поддерживаются типы ресурсов Passbolt v5.
- Другой Passbolt MCP на GitHub ([mapix-etnc/passbolt-mcp-server](https://github.com/mapix-etnc/passbolt-mcp-server), AGPL) без CI; [bitwarden/mcp-server](https://github.com/bitwarden/mcp-server) — официальный вариант для Bitwarden, не для Passbolt.

## Ленивая загрузка инструментов

Ленивая загрузка инструментов (опционально): `PASSBOLT_TOOL_LOADING=lazy` стартует с небольшим ядром и `passbolt_enable_toolsets`, остальные наборы включаются по запросу (`tools/list_changed`). Стоимость старта (tools/list + instructions, ≈символы/4): eager ≈2448 токенов, lazy ≈1048 токенов (−57%). По умолчанию `eager` — без изменений; если клиент не поддерживает `tools/list_changed`, оставьте `eager` или переподключитесь после включения. Область: включение действует в пределах MCP-сессии (session visibility FastMCP), включённые одним клиентом наборы не видны другому. HTTP-транспорт здесь stateless (каждый запрос — отдельная сессия), поэтому включение там не сохраняется: для общего HTTP используйте `eager` или `PASSBOLT_TOOLSETS`.

Клиенты и `notifications/tools/list_changed` (проверено по официальной документации, changelog или заявлениям мейнтейнеров, 2026-10):

| Клиент | `tools/list_changed` | Источник |
|---|---|---|
| Claude Code | Да (интерактивно: tools, prompts, resources; `-p`/Agent SDK: только tools) | [docs: Dynamic tool updates](https://code.claude.com/docs/en/mcp) |
| VS Code (GitHub Copilot) | Да (dynamic tool discovery); новые инструменты могут стать доступны агенту только со следующего хода | [docs](https://code.visualstudio.com/api/extension-guides/ai/mcp), [#303012](https://github.com/microsoft/vscode/issues/303012) |
| Gemini CLI | Да (обновляет реестр инструментов) | [PR #14375](https://github.com/google-gemini/gemini-cli/pull/14375), [PR #21050](https://github.com/google-gemini/gemini-cli/pull/21050) |
| Cursor | Ненадёжно: регрессия в 3.12.x подтверждена командой Cursor; после включения перезапустите Cursor | [forum](https://forum.cursor.com/t/mcp-server-regression-does-not-reload-tools-disconnect-does-nothing-ignores-mcp-json-changes-etc/166216) |
| Claude Desktop, Windsurf, Codex CLI, Cline, Zed, Continue | Не проверено: официальных данных нет; используйте `eager` или переподключитесь после включения | — |

- Проект активно поддерживает ZAI.ONE: текущая версия 0.5.0; изменения в [CHANGELOG.md](CHANGELOG.md) и [Releases](https://github.com/zai-one/passbolt-mcp/releases).
- Встроенная проверка обновлений: попросите ассистента вызвать `passbolt_check_update` (публичный GitHub API, без учётных данных, с кэшем; ничего не устанавливается автоматически; отключение: `PASSBOLT_DISABLE_UPDATE_CHECK=1`).
- Следует актуальным практикам MCP: аннотации инструментов (read-only / destructive), наборы инструментов и режим только чтения, `instructions` сервера, промпты и ресурсы, структурированные ошибки с подсказками, секреты не попадают в ответы, бюджет токенов описаний проверяется в тестах.
- CI прогоняет тесты на Linux и Windows для каждого pull request.

## Установка

Хотите установить готовый пакет? [Установка релиза и создание конфигурации клиента](INSTALL.md#install-a-release-package) работают без клонирования исходников.

Нужны **Python 3.12–3.14** и [uv](https://docs.astral.sh/uv/getting-started/installation/). Можно клонировать проект через Git или [скачать ZIP](https://github.com/zai-one/passbolt-mcp/archive/refs/heads/main.zip). Для ZIP откройте распакованный каталог и пропустите первые две команды.

Установите GnuPG и подготовьте служебную учётную запись Passbolt, её GPG-ключ и пароль к нему, а также политику доступа к хранилищу. Выполните [подготовку Passbolt](INSTALL.md#from-a-clone-or-source-zip) перед командами ниже. Настройщик использует готовые файлы; учётную запись и ключи он не создаёт.

```sh
git clone https://github.com/zai-one/passbolt-mcp.git
cd passbolt-mcp
uv sync --frozen --extra standalone
uv run --frozen --extra standalone python scripts/configure.py
uv run --frozen --extra standalone passbolt-mcp --config mcp.local.json --check-config
```

Настройщик создаёт локальную конфигурацию и сохраняет секреты в приватных файлах. Если конфигурация уже существует, он не перезапишет её. `--check-config` проверяет локальные настройки; доступ к аккаунту проверяется первым запросом ниже.

## Подключение к ассистенту

Добавьте конфигурацию в MCP-клиент, использующий раздел `mcpServers` (например, Claude Desktop или Cursor). Замените `/ABSOLUTE/PATH/` своим абсолютным путём; на Windows в JSON можно использовать `D:/Tools/`.

```json
{
  "mcpServers": {
    "passbolt": {
      "command": "uv",
      "args": [
        "--directory",
        "/ABSOLUTE/PATH/passbolt-mcp",
        "run",
        "--frozen",
        "--extra",
        "standalone",
        "passbolt-mcp",
        "--config",
        "/ABSOLUTE/PATH/passbolt-mcp/mcp.local.json"
      ]
    }
  }
}
```

Клиент сам запускает MCP-сервер. После обновления списка инструментов отправьте первый запрос. Для другого формата конфигурации используйте те же `command` и `args`; `uv` должен быть доступен процессу клиента.

### Первый запрос

> Проверь подключение через passbolt_status, затем найди запись, к которой у меня есть доступ.

При настроенном хранилище вы получите статус подключения и расшифрования, затем метаданные найденных записей. Пароли в ответ не входят. Если настройка не завершена, поля статуса помогут понять, что ещё подготовить.

Если инструменты не появились, проверьте абсолютный путь, доступность `uv` и результат `--check-config`. Для ошибки доступа проверьте учётные данные и права аккаунта. [Подробная установка и диагностика](INSTALL.md).

## Управление доступом и ограничения

Начните с чтения. Создание и изменение записей, а также передача секретов требуют отдельных прав и настроек сервера. Обработчик настраивается оператором: проект не обещает автоматическое заполнение любой формы входа в браузере или приложении.

Записи с PIN-кодом (Passbolt 5.12+) находятся по названию и описанию, но сам PIN никогда не возвращается и не передаётся обработчикам: это не учётные данные для URL. При обновлении такой записи меняются только название и описание, запись остаётся PIN-кодом, а сам PIN не меняется. Обновление записей других типов, кроме паролей, отклоняется.

Новые секреты создаются сервером либо поступают через отдельно подготовленный серверный файл. Инструмента для передачи открытого пароля через MCP в этой версии нет. Подробнее: [работа с секретами и подтверждения](docs/RUNTIME.md).

Для работы по сети предусмотрен HTTP с проверкой токенов. [Настройка HTTP](INSTALL.md#http), [конфигурация и права](docs/RUNTIME.md), [подключение Python-пакета](INSTALL.md#python-package-and-platform-integration).

## Подтверждение шаринга и opt-in наборы

Прямо перед выполнением одобренного шаринга сервер спрашивает пользователя через MCP elicitation. `PASSBOLT_SHARE_ELICITATION`: `auto` (по умолчанию) спрашивает, только если клиент поддерживает elicitation, иначе достаточно подтверждения оператора; `required` отказывает, если клиент не умеет спрашивать; `off` отключает вопрос. Подтверждение оператора нужно всегда. `PASSBOLT_TOOLSETS=default,directory,organize` добавляет `passbolt_directory` (UUID и имена групп и пользователей, разрешённых политикой привязки для шаринга, без email; права на ресурс) и, с подтверждением оператора, `passbolt_move_resource`, `passbolt_move_folder`, `passbolt_unshare` (снимает права пользователей и групп, права владельца не трогает). Карта инструментов: `passbolt://guide/tool-map`.

## Обновления

Попросите ассистента вызвать `passbolt_check_update`. Инструмент сравнивает установленную версию с
[последним релизом](https://github.com/zai-one/passbolt-mcp/releases) через публичный GitHub API
(без токенов и без обращения к хранилищу, таймаут 3 секунды, результат кэшируется на 24 часа рядом с файлом состояния)
и возвращает текущую и новую версии, ссылку на описание релиза и команду обновления
(`git pull --ff-only && uv sync --frozen --extra standalone` для клона, `uv tool install --force ...` для релизного пакета).
Если о новой версии уже известно из кэша, сервер один раз упоминает её в стартовых инструкциях и в
`passbolt_status`. Ничего не устанавливается автоматически. Без сети проверка возвращает `status: unknown`,
а сервер продолжает работать; после неудачного запроса следующая попытка — не раньше чем через 30 минут,
принудительная проверка — не чаще раза в минуту. Принимаются только обычные теги версий вида `v1.2.3`.
При запуске сервер сам делает этот анонимный запрос к `api.github.com` не чаще раза в сутки, в том числе в
HTTP-развёртывании. Отключить: `PASSBOLT_DISABLE_UPDATE_CHECK=1`, например на серверах без выхода в интернет.
